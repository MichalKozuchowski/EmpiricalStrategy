## Core theme
Convert **unstructured scraped data into structured, analysis-ready data**: rows × columns, one type per column. Scraped data almost never arrives in the shape you need.

## Tools covered (what each is for)
- **BeautifulSoup (bs4):** parses HTML into a navigable tree, so you can pull tagged elements (product IDs, prices, links). It's likely running under the hood when Claude scrapes a site.
- **Regular expressions (regex):** extract patterns (prices, star ratings, inventory counts) from raw text. You don't need to write them by hand: give Claude an example and it generates the pattern.
- **JSON:** complex sites often **embed the data as JSON** in the page (e.g. `window.__APOLLO_STATE__`, `window.current_project`).
  - Ask Claude: "Is there JSON in the background I can grab directly?"
  - Then it's an instant DataFrame (`pd.read_json`, `json_normalize`), with no HTML parsing.
- **glob:** lists all files matching a pattern, for batch processing.
  - Caution: it builds the whole list in memory. With millions of files, ask for a **lazy** alternative (`glob.iglob`, `os.scandir`).
- **multiprocessing:** runs the same function across many cores at once.
  - A Pool of 4 was shown live; cluster nodes go up to 128.
  - **Don't request more cores than you have.** Tune incrementally (4 → 8 → 16).

## PDF / unstructured tips
- **TSA throughput exercise:** a 996-page PDF, updated weekly, with **at least 7 format versions over time**.
  - Most students couldn't convert it in 3 minutes with AI alone.
  - The best approach: **ask Claude to inspect and describe the file's structure *before* converting.**
- **Adobe Acrobat** can batch-export PDFs to Excel via saved Actions. That's faster than AI for one-off conversions.
- Ask Claude **"What is the best tool for this job?"** before defaulting to Python.
- (Ours: `pdfplumber` + multiprocessing converted 1,379 pages to a 54,060-row CSV in about 66 s. The blank group cells needed **fill-down**, wrapped codes needed joining (`MD\nW` → `MDW`), and repeated page headers were dropped. Validated by matching daily totals to TSA's published 2–2.7M/day.)

## Prompting tips
- Have Claude write a **journal / README** of how it scraped a site (which attributes, where variables live), so it can adapt when the site changes.
  - Example: "Scrape walmart.com for LEGO prices daily; log where prices were found and what attributes to use."
- Use **web developer tools (Inspect)** to see the HTML structure before prompting.
- If scraping is blocked, **try another model**: Claude refused after 3 attempts on Home Depot's bot detection, and Codex succeeded.
- **Suggested skill template:**
  1. Try `curl`, then `requests` if blocked.
  2. Use multiprocessing if the directory is large.
  3. **Prioritize JSON extraction over HTML parsing.**

## Quiz takeaways (Oct 15)
- Scraped data must be **parsed and converted** before analysis (unwrap, decode, flatten, text → numbers).
- **Look for embedded JSON before parsing HTML.** It's cleaner and more robust.
- **Inspect the structure before converting** (PDF formats change over time).
- glob is eager (a list in memory); lazy alternatives exist. multiprocessing speeds up **independent** files; don't oversubscribe cores.
- **Disguised missing values** in scraped data: "$0.00" prices, St. Jude "items", cancelled pledges, a snapshot taken years after the campaign.
- **Panel construction from irregular snapshots:** pick a fixed grid, carry the last observation forward (never use future snapshots), flag filled rows.
- **Validate an extraction** against an independent source (audit table, published totals, the professor's function on a sample).
